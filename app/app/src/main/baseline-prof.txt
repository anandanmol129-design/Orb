# Baseline profile rules for the Orb launcher (hand-written).
#
# Covers the cold-start and first-frame hot path:
#   - Application/Koin startup: LauncherApplication (org.koin.* is intentionally excluded;
#     third-party libraries ship their own baseline profiles)
#   - Launcher entry points: SharedLauncherActivity + LauncherActivity / AssistantActivity
#   - First frame: ProvideSettings / ProvideCurrentTime / LauncherTheme,
#     LauncherScaffold + LauncherScaffoldVM, OrbHomeComponent / OrbSphere / OrbShapes,
#     ClockWidget + parts (widgets/clock/parts)
#   - Search VM first-use classes: SearchVM, SearchableItemVM
#
# Format (ART human-readable profile):
#   - `Lclass;`            class rule (no flags allowed on class rules)
#   - `HSPLclass;->**(**)**`  hot/startup/post-startup rule for every method of a class
#   - `Class$*;`           companion objects, nested classes, and synthetic/lambda classes
# Wildcards: `?` = one character, `*` = one name part, `**` = anything.
# AGP expands these wildcards against the compiled program
# (ExpandArtProfileWildcardsTask) before packaging the profile.
#
# To regenerate this profile later with a macrobenchmark:
#   1. Add a `com.android.test` module with the `androidx.baselineprofile` plugin, targeting
#      :app (see https://developer.android.com/topic/performance/baselineprofiles/create-baselineprofile).
#   2. Write a BaselineProfileRule test that starts the launcher and exercises the home
#      screen, clock widget and first search (uiAutomator { startApp(...) } etc.).
#   3. Run `./gradlew :<baseline-profile-module>:generateBaselineProfile` on a rooted
#      device (API 33+) or a Gradle-managed device and replace this file with the generated
#      `baseline-prof.txt` output.
